[benchmark_nist_questions.json](benchmark_nist_questions.json) is the public prompt and
answer-shape profile. It contains no expected answers, answer excerpts or literal bindings.
Superseded references and scores are retained in Git history.

This is an **AI-assisted development transcription requiring independent review**.
It is not a blind benchmark result, a claim of verified key correctness, or a new system
score. Expected values came from the original answer key, not our extracted facts or runs.
The old reference was an index and transcription aid, not the definition of required fields.

## What is evaluated

Answers are neutral JSON: properties, paths, tables, timestamps, counts, booleans and
content. They are not restricted to Lean fact kinds. An answer may be independently
generated by any tool; our application must still justify its own output through its
separate proof policy. Matching the key does not itself certify an answer's evidence.

All 60 questions remain in the manifest. At this checkpoint **46 are provisionally
scorable and 14 are explicitly unevaluable** pending reference or contract review.
Those 46 are not the old 47-question closed-book subset. Unevaluable means the reference
is not ready to decide the full question; it is not a system failure or a zero answer.
Candidate values for those questions are retained for review, not awarded partial truth.

The scorer performs typed comparisons. It does not use an LLM to interpret reports.
FOUND/PARTIAL/MISSED-style labels are a structured adaptation, not a claim that a
deterministic matcher reproduces every judgment in Mulder's prose-report rubric.
An answer outside the key is not automatically a forensic false positive.

## Source binding is not semantic proof

The source text and PDF have file hashes. Every question has an inclusive, one-based
`source.start_line` / `end_line` range, source pages and the SHA-256 of:

```python
"\n".join(source_lines[start_line - 1:end_line]) + "\n"
```

All 60 source-span hashes were checked. **1,009 exact string leaves** have `field_sources`
entries naming their JSON pointer, literal and source line range. These literal checks
passed. There are 1,793 string leaves total; unbound strings include normalized wrapped
text, derived timestamps and interpreted labels. Missing bindings are not fabricated.
The PDF was rendered for visual inspection of pages 40 and 54; its hash binds the images
that text extraction cannot capture. Section 3 has extra source spans for Q58 and Q60.

These checks establish that cited source bytes and literal strings have not changed.
They do **not** prove correct field association, complete transcription, timezone choice,
causal interpretation, visual identity or factual correctness of the original answer key.
Repeated literal occurrences are flagged; the first shortest matching span is an anchor,
not a proof that it is the right occurrence. Independent review must inspect the context.

## Normalization and unresolved cases

PDF line wrapping is joined for paths/URLs and collapsed for prose. Windows paths use
single separators and omit trailing directory separators; individual notes identify
other normalization. Sizes retain printed units/precision. Blank, N/A and dash cells
use literal null where appropriate; inability to answer uses submission status `unknown`.
List order is ignored unless explicit step numbers carry sequence. Duplicate rows remain.

UTC timestamps use printed offsets when supplied; otherwise local-time captions use
America/New_York provisionally. Q6/Q10 remain unresolved instead of inheriting the old
reference's inferred UTC-5. Two-second comparison tolerance does not repair semantic
differences between event time, modification time and observation time. Q59 preserves
minute precision as local-minute strings. The two truncated Q15 URLs use declared prefix
matching; absent suffixes were not guessed.
