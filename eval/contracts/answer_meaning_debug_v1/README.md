# Explicit answer-meaning diagnostic

This is a separate public, three-question development profile. It has no private answer key and no accuracy score. It does not replace or change the frozen 60-question test.

It makes the intended field meaning explicit through `x-claim-requirement`. The current claim catalog cannot establish the stronger product/use, complete-copy-path and anti-forensic-action roles. The `answer` tool reports those missing roles and the evidence needed. Separate observation fields accept the narrower existing claim roles, so useful evidence remains reportable.

Q18 now explicitly requests a source-supported product/version identity linked to email use. This is a stronger public declaration than the original short prose prompt, whose strict scoring required a product/version name. Do not call this profile the identical benchmark or claim a new score for it.

Use `questions.json` as an explicit public question profile in a new investigation. The program can report preflight requirements without any model call. Do not apply this profile retrospectively to the frozen outputs. See [the diagnosis](../../../docs/INCORRECT_ANSWER_DEBUG.md) for the exact failures and proof scope.

Compatibility is a deterministic check against declared claim roles. It is not a Lean theorem about the meaning of a question. A poorly specified public requirement can still allow an inappropriate answer. Unknown, incompatible and missing fields remain visible. No rule here certifies list completeness, parser correctness or zero false positives.
