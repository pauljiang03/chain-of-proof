# Sol 6.1 NIST claim-binding development comparison

Lean feedback did not improve overall answer quality in this single pair. A and C each answered 28 scorable questions with some correct content. C had one fewer unanswered question, but one fewer fully correct answer, one more incorrect answer, and 67 fewer matched reference atoms. ## Demonstrated export gap

Every unsupported binding had reason `unsupported_schema_reference_or_union`. The frozen projector did not traverse the public `anyOf` alternatives. It dropped 120 A bindings and 96 C bindings: 67 and 43 respectively concern scorable questions; 53 in each arm concern unresolved questions Q6, Q10, Q29 and Q33. This is an implementation export gap, not a model selector-name error or a Lean proof failure.

Five scorable questions in each arm—Q11, Q22, Q45, Q55 and Q56—had their attempted bindings dropped and remained unanswered. This does not explain every unanswered question or establish that the dropped values would have been correct. A separate post-measurement fix now supports fields explicitly shared by all public `anyOf` alternatives, with compatible types. It does not choose branches or change claim values. This report does not reproject or rescore the frozen trial, and the fix has no new accuracy score. The detailed coverage/export audit is retained in the local archive.

## Claim checks and tool failures

A submitted 63 exact whole candidates. B replayed all 63 in order with zero model calls, accepted all 63, and retained 63 successful independent verification receipts. No B candidate was refused, malformed, unsupported or an execution error. B’s frozen answer fields and conflict omissions were authenticated and unchanged.

C made 71 check calls yielding 103 responses: 102 verified responses, including six duplicates, and one refusal. Its proposal ledger contains 97 unique findings: 96 verified and one refused. All 96 retained certificates independently reverified. The sole refusal, A069/Q39, used a singleton `both` wrapper around `contentHashed`; it was a malformed claim, not a demonstrated semantic predicate mismatch. Q39 is an unresolved reference question.

Neither arm recorded a demonstrated semantic-predicate refusal. This run therefore does not demonstrate detection of a forensic false claim. Accepted certificates do not certify question relevance, schema placement, complete inventories, parser correctness or source authenticity.

A had one non-check bridge error: `plan` was supplied an unsupported `question_id` argument (Q22). C had the same argument error for Q23 and a separate inventory-page error for Q16. The saved inventory sequence strongly indicates a missing continuation cursor; the receipt lacks an exception message, so the exact throwing guard remains an explicit code-derived inference. These errors are distinct from claim refusals. Detailed B and C refusal audits are retained in the local archive.

Both investigators completed voluntarily before the cap, closed their bridges, and produced valid binding documents. No timing reminder or budget extension was needed. Finalization and offline verification/scoring occurred after the recorded investigator times. Elapsed times conservatively include dispatch/observation overhead and do not establish a speed improvement.

The requested model was `gpt-6.1-sol`, with fresh `fork_turns=none` contexts, one A run followed by one C run, and identical public inputs, seven-tool interfaces and 900-second caps. A’s outputs and the private key were not supplied to C. The coordinator froze/validated reference metadata before launch and scored only after both investigators stopped. Actual provider revision, token usage, reasoning effort and cost are not independently observed. Isolation is procedural, not an OS sandbox. Other authorized work could run on the machine. This does not validate the native product model backend.

This v2 run uses fresh extracted facts and a common claim-linked export. The old v1 pilot scored literal unverified answer blocks. Score differences between those protocols are not an apples-to-apples measurement of improvement, and the original pilot remains unchanged. This is a single development pair, not a statistically established advantage or the completed A/B/C/D experiment.

## Incorrect answer diagnosis

The saved score audit identifies three wholly incorrect C answers:

- Q18 projects `OUTLOOK.EXE` as the application name. This does not supply the requested product name and version.
- Q34 projects journal path suffixes with an unresolved ancestor as the requested full staging paths. The formal observation explicitly permits an incomplete suffix; it does not prove a complete historical path or a completed copy.
- Q52 projects file-removal observations as the anti-forensics activity list. Those observations do not establish the requested actions, methods or complete sequence.

These are answer selection and interpretation problems. No answer-key change was made.
Shared schema support does not fix them. Missing source metadata, incomplete inventories,
and unsupported relationships remain separate work. The largest matched-field change was Q44
(Internet Explorer traces in Windows Search): 92 in A and 12 in C. Q46 moved from 4 to 46.
Neither question had dropped schema bindings, so the schema fix does not explain this coverage difference.
